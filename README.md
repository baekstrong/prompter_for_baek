# Prompter for Baek · 프롬프터

아이폰 전면 카메라로 촬영하면서 대본을 읽는 개인용 웹앱입니다. 별도 유료 API나 서버 없이 대본과 영상을 브라우저 안에서 처리합니다.

## 실행

- 사용 주소: https://prompterforbaek-dist.vercel.app (Vercel 무료 플랜, main 푸시 시 자동 배포, 링크를 아는 누구나 접속 가능)
- 이전 주소: https://prompter-for-baek.rich-mango-0430.chatgpt.site (소유자 전용 Sites 배포, 수동 배포)
- 아이폰 Chrome 또는 Safari로 열고 카메라·마이크 접근을 허용합니다.
- 브라우저 공유 메뉴 → **홈 화면에 추가**로 설치할 수 있습니다.
- 대본을 붙여 넣고 **읽기 연습**으로 속도를 맞춘 뒤 **녹화 시작**을 누릅니다.
- 종료 후 **공유 / 사진에 저장**에서 기기가 제공하는 저장 메뉴를 선택하거나 **파일로 저장**을 누릅니다. 사진 앱 자동 저장은 하지 않습니다.

## 구현 기능

- 대본 편집·TXT 불러오기·자동 저장, 문장 줄바꿈과 문단 간격 보존
- 드래그 및 방향키로 대본 위치 이동, 글자 크기·폭·배경 농도·속도 조절
- 자동 스크롤·대본만 일시정지/재개·처음으로, 키보드 Space 재생/일시정지
- 전면/후면 카메라·마이크 녹화, 0/3/5초 카운트다운
- 촬영 화면 확대, 가로/세로 레이아웃, 미리보기 좌우 반전
- 대본이 포함되지 않는 원본 영상, MP4 우선 지원 여부 확인 후 WebM 대체
- 기기 보관함·재생·공유·다운로드·개별 삭제
- 1초 간격 녹화 청크 저장 및 중단된 촬영의 저장 구간 조회
- 화면 꺼짐 방지 요청, 카메라 끄기, 앱 전환·입력 중단 시 녹화 종료
- 오프라인 앱 셸. 업데이트로 촬영 중인 페이지를 강제 재시작하지 않습니다.

## 0.1.1 · 아이폰 홈 화면 스크롤 수정

- 매 프레임 DOM의 정수 스크롤 위치를 다시 읽지 않고, 소수점 이동량을 별도로 누적합니다. 낮은 속도 및 60/120Hz에서도 정지하거나 속도가 달라지지 않도록 수정했습니다.
- 화면 아래 **앱 버전 0.1.1**을 확인하세요. 기존 홈 화면 앱은 인터넷에 연결한 뒤 완전히 닫고 다시 열면 수정본을 받을 수 있습니다. 새 버전 안내가 뜨면 대본 재생·녹화를 마친 뒤 **업데이트 적용**을 누릅니다.
- **업데이트 확인** 버튼도 추가했습니다. 대본과 촬영 보관함은 유지하며, 촬영 중 강제 새로고침이나 브라우저 데이터 삭제를 하지 않습니다.
- 최초 v1 앱의 오래된 캐시를 통과하도록 주 스크립트·스타일 URL에 버전을 붙였습니다. 서비스 워커는 같은 버전의 HTML·에셋을 함께 사용합니다.
- 스크롤 회귀11개(60/120Hz × 8/32px/s × 정수 반올림/버림, 되돌리기·수동이동후재개·끝에서재생)와 PWA 업데이트 회귀를 포함해 총36개 테스트를 통과했습니다. 실제 사용자 아이폰에서의 수정 확인은 별도입니다.
- 근거: [WebKit scrollTop 정수 IDL](https://raw.githubusercontent.com/WebKit/WebKit/main/Source/WebCore/dom/Element%2BCSSOMView.idl), [소수 scrollTop 지원 이슈](https://bugs.webkit.org/show_bug.cgi?id=188045). Chrome에서 홈 화면에 추가하는 경로 자체는 지원되는 실행 방식입니다.

## 0.1.7 · 카메라 전체화면

- 촬영 도구 모음의 **카메라 전체화면** 버튼으로 미리보기가 화면 전체를 채우고, 상단 도구와 녹화 버튼은 반투명하게 위에 겹쳐 표시합니다. 다시 누르거나 Esc로 끝냅니다.
- 전체화면에서는 미리보기를 화면 비율에 맞게 잘라 보여줍니다. 녹화 파일은 잘리지 않은 원본입니다.
- 브라우저가 지원하면(데스크톱·Android·iPad) 브라우저 주소창까지 숨깁니다. iPhone Safari는 화면 안에서만 확장하므로 홈 화면 앱으로 실행하면 가장 넓게 보입니다.
- 대본 창은 위아래 도구에 가리지 않도록 그 사이에 배치합니다. 앱 **0.1.7**, 서비스 워커 v8입니다.

## 0.1.6 · 점검 수정

- 녹화 중에는 촬영 보관함 버튼을 잠가, 쓰는 중인 영상을 지워 녹화가 끊기는 문제를 막습니다.
- 녹화 시작이 취소되면 비어 있는 보관함 항목을 지웁니다.
- 가로 화면 도구 모음이 노치·Dynamic Island 아래로 들어가지 않게 했습니다.
- 키보드로 TXT 불러오기 버튼에서 Space를 누를 때 대본 재생이 같이 토글되지 않습니다.
- 앱 **0.1.6**, 서비스 워커 v7입니다.

## 0.1.5 · 넓은 프롬프터 창과 독립 크기 조절

- 가로 창을 CapCut 참조처럼 넓혀 기본 너비58%·높이76%로 표시하고, 화면 가장자리에서13% 안쪽에 배치합니다. 반대쪽 기본 위치는 대칭으로 적용합니다. 세로 기본 창은 너비94%·높이40%입니다. 화면과 도구 모음에 겹치지 않도록 실제 크기는 사용 가능한 영역 안에서 제한합니다.
- 설정의 **창 너비·창 높이**로 프롬프터 화면 크기를 따로 조절합니다. **글자 크기**와 **창 안의 대본 폭**은 내부 글자와 글줄만 바꾸며 외부 창의 위치·너비·높이는 바꾸지 않습니다.
- 세로·가로의 창 크기와 위치를 각각 저장합니다. 손잡이로 화면 안에서 자유롭게 이동할 수 있고, **위치·크기 초기화**는 현재 방향의 창만 기본값으로 되돌립니다.
- 기존0.1.4의 좁은 창과 제한된 위치는 새 기본 창으로 이전합니다. 대본과 글자·속도·배경 설정, 촬영 보관함은 보존합니다.0.1.4의 카메라 복구·일반 렌즈 선택 기능은 유지합니다.
- 앱 **0.1.5**, 서비스 워커 v6입니다. 기존 홈 화면 앱에서 업데이트 확인 후 완전히 닫고 다시 열어 버전을 확인합니다.

## 0.1.4 · 카메라 복구·기본 화각·렌즈 가까운 대본창 (이전 배치)

- 화면을 보고 있는 중 미리보기만 일시정지되거나 멎으면 같은 촬영 스트림으로 재생을 다시 시도합니다. 종료된 입력을 정상 카메라로 재사용하지 않고, 녹화 전 연결 종료에는 한 번 재연결합니다. 앱 복귀 시에도 입력과 재생 상태를 확인합니다.
- 순간적인 입력 중단은 안내 후 회복을 기다립니다. 5초 동안 계속 카메라·마이크 입력이 없거나 연결이 실제 종료되면 저장된 구간을 보관하고 녹화를 종료합니다. 녹화 중 다른 스트림으로 몰래 교체하지 않습니다. 화면 잠금·앱 전환 시 종료 정책은 유지합니다.
- 전후면의 일반 카메라를 장치 정보로 구분할 수 있으면 해당 렌즈를 우선 선택하고, 지원 기기는 실제 촬영 트랙의 확대를 1배로 맞춥니다. 미리보기와 저장 영상 모두에 적용합니다. 기기가 렌즈 정보를 제공하지 않으면 브라우저 선택을 사용합니다. 기본 카메라 앱의 셀피 자동 확대·구도·보정까지 완전히 같다는 보장은 없으며 iPhone 실기기 비교가 필요합니다.
- 모바일에서 카메라를 켜거나 녹화를 시작하면 집중 화면으로 전환하여 대본을 렌즈 가까이 표시합니다. 확대 버튼으로 기본 화면에 돌아갈 수 있습니다. 세로 대본창은 상단의 작은 영역, 가로 대본창은 렌즈가 있는 좌우 가장자리의 좁은 영역에 표시합니다. 설정의 **가로 렌즈 위치**에서 자동/왼쪽/오른쪽을 선택할 수 있습니다. 기존 중앙 위치 설정은 렌즈 근처로 이동하고, 글자 크기·속도·줄바꿈과 문단은 유지합니다.
- 앱 **0.1.4**, 서비스 워커 v5입니다. 인터넷에 연결한 기존 홈 화면 앱에서 **업데이트 확인** 후 완전히 닫고 다시 열어 버전을 확인합니다. 기존 대본·촬영 보관함은 유지합니다.

입력의 일시 중단과 종료 구분은 [W3C 미디어 트랙 수명](https://w3c.github.io/mediacapture-main/#life-cycle-and-media-flow), 기본 렌즈 선택 이력은 [WebKit 후면 카메라 이슈](https://bugs.webkit.org/show_bug.cgi?id=253186), 확대 지원은 [Safari 17 WebKit 안내](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/)를 참고했습니다. 사용자 기기의 끊김 원인을 직접 계측하거나 장시간 촬영을 검증한 상태는 아닙니다.

## 30분~1시간 촬영 기준과 확인 사항

사용자의 일반적인 촬영 길이는 **보통 30분, 1시간 이내**입니다. 영상 4Mbps·음성 128kbps를 요청하므로 30분은 대략 0.93GB, 1시간은 1.86GB 수준이지만 실제 용량·화질은 브라우저와 기기에 따라 다릅니다. 녹화 시간을 임의로 제한하지 않으며 해당 길이의 실기기 검증은 아직 하지 않았습니다.

- 해상도 1920×1080, 30fps를 ideal로 요청하고 실제 카메라 설정을 설정창에 표시합니다. 기기가 더 낮은 설정을 반환할 수 있습니다.
- 녹화 중 청크는 IndexedDB에 순서대로 보관하고, 저장이 끝난 청크는 메모리 큐에서 제거합니다. 저장 오류나 미저장 청크 64MiB 도달 시 자동 종료하여 회수 가능한 영상을 제공합니다. 브라우저가 마지막에 생성하는 청크의 크기까지 앱이 제한할 수는 없습니다.
- 화면의 여유 용량은 **브라우저 저장 할당량 추정치**이며 기기 물리 저장 공간과 다를 수 있습니다. 보관함 영상은 필요한 만큼 파일로 내보낸 뒤 사용자가 삭제해야 합니다.
- 페이지가 강제 종료되면 이미 저장된 청크만 남습니다. 중단된 파일의 재생 가능성과 마지막 구간 보존은 녹화 형식·종료 시점에 따라 달라집니다. 완전한 복구를 보장하지 않습니다.
- 화면 잠금·앱 전환·전화 등으로 입력이 중단되면 촬영을 종료합니다. 촬영 중 방향을 바꾸지 마세요. 전면 미리보기만 좌우 반전하고 녹화 파일에는 적용하지 않습니다.
- iPhone 모델·iOS 버전은 아직 확인하지 않았습니다. 실제 아이폰에서 ① 10초 영상의 방향·음성·저장 ② 30분 연속 촬영·싱크·발열 ③ 평소 최대 길이 촬영 순서로 확인이 필요합니다.
- iOS Safari 세로 녹화에는 [기기별 방향 문제 보고](https://bugs.webkit.org/show_bug.cgi?id=323550)가 있습니다. 세로 촬영 파일의 방향은 실기기에서 확인해야 합니다.

대본은 localStorage, 촬영 영상은 IndexedDB에 보관합니다. 브라우저 데이터 삭제·비공개 모드·OS의 저장 공간 회수로 자료가 없어질 수 있으므로 필요한 영상은 파일/사진 앱에 저장해 주세요. 앱이 대본이나 영상을 서버로 업로드하지는 않습니다.

## 로컬 개발

Node.js 20 이상. 런타임 의존성이 없고 설치/빌드 없이 실행됩니다.

```sh
npm run dev
# http://127.0.0.1:4173
npm run check
npm test
```

HOST·PORT 환경변수로 수신 주소를 바꿀 수 있습니다. 아이폰에서 LAN의 일반 HTTP 주소로 접속하면 카메라를 사용할 수 없으므로 HTTPS 배포 주소를 이용합니다. dist/ 전체를 정적 호스팅에 올리면 됩니다. GitHub 저장소 baekstrong/prompter_for_baek를 Vercel 프로젝트 prompter_for_baek-dist(Root Directory: dist, Framework: Other)에 연결해 배포합니다. 유료 API나 결제를 추가하지 않았으며 서비스의 향후 요금 정책은 별도입니다.

## 검증

- npm test: 카메라 상태/권한·취소 경합·최종 청크·IndexedDB·저장 오류·입력 중단, 대본 설정/스크롤, 서버/PWA 테스트.
- 선택 브라우저 통합 검사: Playwright를 별도로 준비하고 서버 실행 후 node scripts/browser-test.mjs를 실행합니다. 외부 Playwright 모듈과 브라우저는 PROMPTER_PLAYWRIGHT_MODULE, PROMPTER_BROWSER_PATH로 지정할 수 있습니다.
- Chromium 가상 카메라·음성으로 대본 보존, 스크롤, 준비 취소, 1080p 녹화·재생·다운로드, 재접속 복구, 오프라인 실행, 393px 세로/852px 가로 레이아웃을 확인했습니다. 이는 실제 아이폰이나 30분~1시간 촬영 검증을 대신하지 않습니다.
- 로컬 스크린샷과 테스트 영상은 .artifacts/에 생성하고 Git 및 배포 소스에서 제외합니다.

## 0.1.2 · 업데이트 후 Safari 접속 오류 복구

0.1.1 서비스 워커가 리다이렉트 이력이 있는 캐시 HTML을 그대로 반환해 Safari에서 `Response served by service worker has redirections`가 발생할 수 있었습니다.

- 실제 앱 문서인지 고유 마커·MIME으로 확인한 뒤 새 Response로 재구성하여 리다이렉트 이력을 제거합니다.
- 로그인·인증 콜백은 가로채지 않고, 로그인 HTML을 앱 캐시에 보관하지 않습니다. 온라인 화면은 서버 응답을 먼저 사용하고 오프라인일 때 검증된 앱 셸을 사용합니다.
- 기존 오류 화면에서도 복구 worker가 활성화되도록 앱 셸 저장 실패와 worker 설치를 분리했습니다. 열린 촬영 페이지를 강제 재시작하지 않습니다.
- 대본의 localStorage와 촬영 영상의 IndexedDB는 삭제하지 않습니다. 기존 앱 아이콘 삭제·재설치·웹사이트 데이터 초기화를 복구 방법으로 사용하지 않습니다.
- 복구 후 화면 아래 버전은 **0.1.2**입니다. 기존 홈 화면 아이콘을 인터넷에 연결된 상태에서 열고 업데이트 점검 시간을 준 뒤, 앱 전환기에서 닫고 같은 아이콘으로 다시 실행합니다. iOS에서 적용되는 정확한 시점은 실기기 확인이 필요합니다.
- 리다이렉트·로그인 오염·구버전 캐시·오프라인 복구를 포함한 테스트44개를 통과했습니다. 실제 iPhone 설치본 복구 확인은 별도입니다.
